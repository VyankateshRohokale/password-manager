How it works

Three steps, and your plaintext never touches our database.

  1. 1

    Choose a master password

    Your browser stretches it with PBKDF2 (600,000 iterations) and splits the result into a login key and an encryption key.

  2. 2

    Save your logins

    Each field is encrypted with a random 256-bit vault key and a fresh 96-bit nonce using AES-256-GCM.

  3. 3

    Unlock anywhere

    Log in from any browser. The server returns ciphertext, and your browser decrypts it locally.

Security you can explain

Every safeguard below is implemented in this application and described in the project documentation.

Your master password cannot be recovered. If you forget it, the encrypted data in your vault cannot be decrypted by anyone, including us.
  • Separate keys. HKDF derives independent authentication and encryption keys from your master key.
  • Hashed again on the server. The authentication key is stored only as an Argon2id hash.
  • Authenticated encryption. AES-GCM detects any change to stored ciphertext.
  • Hardened sessions. HttpOnly, SameSite=Strict cookies with CSRF protection and login throttling.
  • Strict content policy. No third-party scripts, fonts or trackers are loaded.
  • Ownership enforced. Every request is scoped to the signed-in account on the server.
